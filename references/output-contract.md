# 结果交付约定

## 小批量聊天输出

先用一段说明主题、时间范围、硬门槛、实际搜索词/排序、采集时间，以及搜索覆盖和停止原因。用户提供摘录时写“基于提供材料”，不声称进行了页面访问。

合格表只放满足全部硬条件且有真实来源链接的笔记；标题缺失时注明未提供，不另编标题。

| 样本 ID | 笔记与原始链接 | 日期 | 赞 / 藏 / 评 | 当前粉丝 | 相关性与入选理由 | 已查看范围 |
|---|---|---|---|---|---|---|

按本次用途删去不需要的列。未知值显示“未读/未知”，近似值显示“约”。作者可并在笔记列。不能删除访问参数来美化链接。

另列待核实样本及缺项；排除项数量大时按原因汇总，必要时附代表例。请求 20 条只找到 7 条，就明确说 7 条，不用弱相关或待核实样本补足。

用户要拆解时，每个重点样本使用：

- 已观察：标题/封面/正文/评论中的具体证据，标明来自哪部分。
- 可能有效的机制：与证据连接，使用假设语气，不冒充后台指标。
- 可以学习：可迁移的组织方法与适用条件。
- 需要自己的材料：事实、体验、操作演示、案例等。

跨样本归纳需引用样本 ID。多个标题相似不等于机制有效；可说明同类样本缺少对照组。必要时保留一两条同主题普通样本作比较。

用户希望转成选题时，给少量“新角度 + 证据来源 + 自有素材要求 + 验证动作”，而不是批量复制原标题。没有个人素材时不编造“我试过”的经历。

## 批量留档

使用不与旧结果冲突的目录，如 `outputs/xhs-viral-radar/<本次日期>-<主题简称>/`；同名批次追加编号。文件可包括：

- `report.md`：可读报告，含覆盖与局限。
- `samples.json`：原始显示、解析值和证据。
- `search-log.json`：搜索参数、实际入口/排序、进度与停止原因。

除非用户明确需要表格文件，不必强制制作 CSV/XLSX。已有导出数据可以保留原格式。

`samples.json` 每条记录包括：

| 字段 | 规则 |
|---|---|
| `sample_id`, `note_id` | 本次报告 ID；笔记 ID 未知可为 null |
| `source_url`, `alternate_urls` | 真实原始链接；可保留多个；未知不编造 |
| `title`, `author`, `author_url`, `content_type` | 实际读到的值；缺失为 null |
| `published_raw`, `published_at`, `date_precision` | 保留日期原文及解析精度 |
| `captured_at`, `source_method`, `evidence_depth` | 采集时区、来源方式、实际阅读深度 |
| `likes`, `saves`, `comments`, `followers` | 各含 `raw`, `value`, `precision`；precision 为 exact / approximate / lower_bound / unknown |
| `qualification`, `qualification_reasons` | matched / pending / excluded 与依据 |
| `queries`, `observations`, `hypotheses`, `missing_fields` | 命中词、观察事实、机制假设、缺项分别保存 |

结构化字段根据任务规模精简，不允许为了满足字段完整性补造数据。多个来源冲突时保留时间戳和冲突说明。

`search-log.json` 至少记录：请求与实际条件、关键词及排序、扫描/去重/合格/待核实数量、最后检查的位置和停止原因。若页面不能可靠续页，按已保存的笔记 ID 去重后继续，不声称可无损恢复页面游标。

## 常用调用

```text
使用 $xhs-viral-radar，找近30天 AI 视频教程领域20条小红书笔记，
点赞至少1000、作者当前粉丝不超过5000，优先我能做操作演示的，拆解前5条。
```

```text
使用 $xhs-viral-radar，搜索收纳产品种草，近60天，高收藏优先。
先给原链接和选入原因，不生成文案；收藏看不到就标未知。
```

```text
使用 $xhs-viral-radar，分析我给的8条笔记，不另外搜索。
分清实际观察和推测，总结适合我自己素材的3种内容结构。
```
